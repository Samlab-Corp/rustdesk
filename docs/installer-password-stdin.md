# 설치 관리자 고정 인증 명령

설치된 `rustdesk.exe --set-permanent-password-stdin`를 정상 관리자 권한으로 실행한다. 기존 명령처럼 설치된 실행 파일과 서비스의 실행 파일 경로가 일치해야 한다. 별도 실행 파일이나 일반 사용자용 내부 통신 경로를 추가하지 않는다.

자동 설정은 비어 있는 상태 또는 입력과 이미 같은 암호만 허용한다. 검사와 갱신은 기존 수동 설정과 같은 서비스 설정 쓰기 잠금 안에서 원자적으로 수행한다. 다른 암호가 있으면 `existing_password_conflict`로 실패하고 메모리·파일·신뢰 기기 설정을 바꾸지 않는다. 기존 `--password` 수동 관리자 변경은 그대로 유지한다.

`rustdesk.exe --verify-permanent-password-stdin`는 같은 권한·입력 계약으로 입력 암호의 일치와 저장 상태만 조회한다. 설정 함수·솔트 생성·파일 저장을 호출하지 않으므로 중단된 설치의 조정에 사용할 수 있다. 읽기 실패·불일치·저장 미확인은 성공으로 취급하지 않는다. 기기 소유권은 설치 조정자의 별도 원장으로 판단하며, 이 명령의 암호 일치만으로 다른 소유권을 새로 획득했다고 간주하지 않는다.

비밀은 표준입력으로만 전달하고 입력을 닫는다. 인수·환경변수·임시 파일·로그에 암호를 넣지 않는다. 입력은 끝의 줄바꿈 한 번을 제외한 8~256바이트의 UTF-8 한 줄이며 제어문자와 빈 입력을 거부한다. 대화형 입력은 거부하고 입력 대기는 10초로 제한한다. 설치·관리자·정책 조건을 먼저 검사하므로 거부된 실행은 비밀을 읽거나 서비스를 변경하지 않는다.

출력은 아래 필드만 있는 한 줄이며 비밀과 그 지문은 포함하지 않는다.

```json
{"id":"기기번호","daemonAccepted":true,"matches":true,"permanentPasswordSet":true,"persisted":true,"serverVerified":true,"reason":"configured"}
```

- `daemonAccepted`: 승인된 서비스가 기존 설정 함수를 통해 요청을 받아들였다.
- `matches`: 현재 유효 암호가 표준입력과 일치한다. 조회 명령의 `daemonAccepted`는 조회를 받아들였다는 뜻이며 설정 변경을 뜻하지 않는다.
- `permanentPasswordSet`: 고정 인증이 설정돼 있고 현재 인증 방식에서도 사용 가능하다. 인증 방식을 임의로 변경하지 않는다.
- `persisted`: 같은 SYSTEM 서비스가 실제 설정 파일을 다시 읽었으며 암호화된 저장값·솔트가 메모리 상태와 같고 입력 암호와도 일치한다. 파일 읽기·해석·비교 실패 시 거짓이다. 기존 저장 함수의 오류를 성공 응답으로 취급하지 않는다.

- `serverVerified`: 서비스가 실제로 선택하는 서버·서버 목록과 공개키가 회사 고정 계약과 일치한다. 실행 파일 이름과 저장된 사용자 지정 주소·키의 우선순위도 확인한다. 불일치하면 고정 인증 설정 전에 실패하며 주소·키·기기번호는 임의로 바꾸지 않는다. 이 값은 확인 시점의 설정 일치이며 네트워크 연결 성공을 뜻하지 않는다.

다섯 값이 모두 참이고 기기번호가 유효한 때만 종료값 0이다. 나머지는 종료값 1이며 `reason`은 정해진 비밀 없는 실패 분류다. 시간 초과나 응답 유실은 자동 재시도하지 않는다. 이미 설정됐을 수 있으므로 설치 조정자가 조회 명령으로 현재 상태를 확인한다. 비어 있던 고정 인증을 실제로 설정할 때는 기존 함수의 정책대로 신뢰 기기 목록을 초기화하며, 같은 암호의 반복 요청과 조회는 이를 초기화하지 않는다.

서비스 측에서도 기존 실행 파일 인증에 더해 관리자 또는 SYSTEM 요청자인지 확인한다. 실제 설정과 파일 재조회는 SYSTEM 서비스에서만 허용한다. 구형 서비스가 새 요청을 이해하지 못하면 확인 응답이 없어 실패한다. 서비스까지 새 판본으로 갱신한 뒤 사용해야 한다.

이 명령의 성공은 현재 고정 인증 설정과 파일 재조회 결과다. 기기 귀속 등록, 장기 무인 연결, 재부팅 후 재연결, 전원 손실 내구성 검증을 대신하지 않는다. 기존 복구 통로는 실제 무인 연결과 재연결을 확인할 때까지 유지한다.

정책 검사는 `src/installer_password_policy.rs`의 단독 Rust 검사로 수행하며 사용자 설정을 읽거나 쓰지 않는다. 검사 실행 파일은 작업별 임시 폴더에 만들고, 증거 로그만 작업 기록에 보존한다.
