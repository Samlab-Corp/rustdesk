# 회사 승인 단일 관리 명령

`samlab-management`는 기존 `samlab-terminal`과 별도인 개발 시험용 단일 명령 도구다. 일반 암호 연결, 터미널 허용과 암호화를 선행 유지하며 명령마다 현재 회사 운영자와 정상 등록 기기의 온라인 승인을 추가한다. 서비스가 SYSTEM이라는 사실만으로 원격 명령을 허용하지 않는다.

## 연결과 실행

기존 `Terminal` 로그인 안의 `native_management` 필드2가 별도 관리 모드를 지정한다. 서버는 신선한 원격 암호 검증 뒤에만 난수32바이트 도전값을 만든다. 이전 세션 캐시는 이 암호 검증을 대체하지 않는다. 기존 일반 터미널은 그대로 유지한다.

구 서버가 이 필드를 무시하더라도 관리 도구는 명시적 관리 도전값을 받기 전 `OpenTerminal`이나 일반 입력을 보내지 않는다. 20초 이내에 관리 도전값이 없으면 유한 실패한다. 새 서버 관리 연결에서도 일반 터미널 입력과 추가 관리 실행을 거절한다.

도구는 `--target <정확한 숫자 주소>`와 선택 `--force-relay`만 과정 인수로 받는다. 암호·현재 운영자 접근 자격·원문 명령·정확한 개발 귀속·작업번호·해시·시간/출력 제한은 표준입력 JSON으로만 받는다. 자격을 파일이나 명령 인수에 넣는 사용 예시는 제공하지 않는다. 표준입력의 `scope.challenge`는 빈 문자열이며 실제 서버 도전값을 받은 뒤 메모리에서 채운다.

고정 `https://dev-kiosk-api-server.letmeup.co.kr/v2/backoffice/kiosk-native-management/grant`에만 운영자 자격을 전송한다. 인증서 검증을 유지하고 우회 주소/프록시/리다이렉트/자동 재발급을 사용하지 않는다. RustDesk 연결에는 운영자 자격 대신 정확한 목적 토큰과 승인된 단일 명령만 보낸다.

서버는 고정 `\\.\pipe\samlab-guardian-native-remote-v1`의 실제 서버번호, 현재 `SamlabGuardian` 서비스, SYSTEM 토큰, KnownFolder ProgramFiles 아래의 보호된 고정 실행파일을 대조한 뒤만 목적 토큰을 보낸다. 경로는 사용자명/드라이브에 고정하지 않는다. 보호된 파일의 열린 손잡이, 재분석점 거절, 소유자/쓰기권한, 볼륨·파일 식별과 사후 서비스번호 대조를 유지한다.

Guardian의 현재 등록 귀속과 고정 개발 API 온라인 검증은 기기 쪽 전역 비밀 없이 승인을 확인한다. 승인 응답의 버전·목적·환경·작업·명령해시·도전값·주소·실제 사용자번호·만료를 정확히 대조한다. 수명60초/발급시각 오차5초에 대응해 응답 잔여시각 상한은65초이며 이미 만료됐으면 거절한다. API 소비/응답 유실 시 자동 재시도하지 않는다.

실행 직전 자기 과정 SID가 `S-1-5-18`인지 다시 확인한다. 로그인 사용자나 탐색기의 토큰을 가져오지 않는다. 고정 시스템 PowerShell의 비대화형 자식은 명령을 받기 전에 종료 보장 작업 객체에 묶는다. 원문 명령은 UTF-8 해시와 동일한 메모리 내용에서 ASCII 표준입력 전송으로 복원하며 과정 인수에 넣지 않는다. 원문 최대16KiB, 시간1~300초, 두 출력 합계 최대1MiB다. 제한/확인 실패 시 자식 전체를 종료하고 미확정으로 처리한다.

## 결과와 확인 경계

결과는 작업번호·상태·고정 이유·실제 SYSTEM 여부·종료코드 확인 여부·제한된 출력이다. 실제 SYSTEM 증명과 종료코드 확인이 모두 있어야 완료로 판정한다. API 감사 소비는 명령 완료 증거가 아니다. 명령 완료도 복구/재접속 완료를 대신하지 않는다. 미확정 명령은 자동 재실행하거나 새 작업번호로 자동 갱신하지 않는다.

현재 실제 기기 SYSTEM 명령, 로그아웃 상태, 수정 후 재조회, 서비스 복구와 재접속은 미검증이다. 지정 시험기기에서 정상 공개키 등록과 개발 승인 뒤 단계별로 실증한다. 다른 지점/운영 환경/일괄 배포는 포함하지 않는다. 기존 일반 원격 도구와 복구 통로를 보존한다.
